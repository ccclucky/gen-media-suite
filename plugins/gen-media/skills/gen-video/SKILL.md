# 生视频

通过用户自己的 New API 网关做文生视频。脚本：本 skill 目录下的 `scripts/gen_media.py`。

> 语言铁律：面向用户的文字一律中文——brief 卡片表头与内容、拍板门、提问、报错解释。送给模型的 prompt 也用中文。脚本 stdout 英文，读完后翻译再回。

## 首次配置（onboard）

1. 跑 `python "<skill-dir>/scripts/gen_media.py" show-config`。
   - 打出 Base URL + 掩码 Key → 配置完成，跳过本段。
   - stderr 含 `CONFIG_MISSING` → 继续。
2. 直接在对话里收 **Base URL** 和 **API Key**（一句话一起问，或分两行收）。
3. 收齐后跑：

   ```bash
   python "<skill-dir>/scripts/gen_media.py" configure --base-url "<url>" --api-key "<key>"
   ```

   Key 只在本次对话出现这一次；之后只用 `show-config` 的掩码输出。

4. 再跑 `show-config` 验证，看到掩码 Key 即完成。

> 安全说明（一句话带过）：Key 写入本地 `~/.gen-media/config.json`（权限 600），经过本次对话一次；介意者用环境变量 `GEN_MEDIA_BASE_URL` + `GEN_MEDIA_API_KEY`（完全绕过对话）。

## 选模型

配置已有 `video_model` 且用户未要求换模型 → 跳过本段。

需要选/换时：

1. 跑 `list-models`，把目录给用户看。
2. 文生视频默认：`happyhorse-1.1-t2v`。`i2v`/`r2v` 需要图片输入，本 skill 只走文本管线，脚本会拒绝。
3. 持久化：`set-model --video <model>`。单次试：生成命令加 `--model <model>`。
4. 完成判定：`show-config` 打出所选视频模型。

## 打磨 brief

先补齐这六个槽位；能从请求推断的就填上并在卡片里标「假设：…」，推断不了且猜错会烧 Credits 时才问（最多问 2 个）：主体+动作（一镜一主体）、环境、镜头（一镜一个运动）、时间线节拍（无节拍=静止帧）、格式（比例/分辨率/时长）、光线与情绪（单一情绪）。

- 模糊请求（「随便来个视频」）→ 给 3 个方向（场景+镜头，每个一行），让用户挑；选完再补其余槽位。
- 默认 `1080P` / `16:9` / `5` 秒；手机/短视频 `9:16`；省额度草稿 `720P`。
- 画面元素=用户点名集合；未点名=画面里不出现。
- ≥2 槽位靠推断，或用户说「更好/优化/换风格」→ 先读 `references/prompt-guide.md`。
- 完成判定：六槽位填好 + 由槽位拼出**最终 prompt 逐字文本** + 格式/模型定好，中文卡片摆出（模板见拍板门）。本步产出=中文卡片，不是文件。

## 拍板门

视频烧 Credits，先让用户拍板。用下面这张**固定中文卡片**摆出 brief（表头与内容一律中文，假设项写「假设：…」）。「最终 prompt」行=逐字送模型的文本；用户拍的就是这串字：

| 槽位        | 内容                                       |
| ----------- | ------------------------------------------ |
| 主体+动作   | …                                          |
| 环境        | …                                          |
| 镜头        | …                                          |
| 时间线      | 0-2s …；2-4s …；末秒 …                     |
| 光线/情绪   | …                                          |
| 最终 prompt | <逐字送模型的中文文本>                     |
| 规格        | <比例> · <分辨率> · <时长>s · 模型 <model> |

卡片下方补一句 affordance：「想换模型/分辨率/时长/任何一格，直接说；说『确认/行/ok』即按此卡逐字生成。」

**拍的是这张卡本身**——最终 prompt 与规格被逐字锁定。提交那一刀必须用卡上的 prompt / 比例 / 分辨率 / 时长 / model，一字不改。

**报错或想降级/换任何参数 → 这次不作数**：重摆一张新卡，让用户重新拍板，才能再消耗额度。绝不静默换模型或偷偷改时长。

判定（满足其一才提交，否则不算拍板）：

- 肯定词（行 / 可以 / 生成 / ok / 确认 / 就这个 / 嗯）→ 提交。
- 修改指令（改环绕镜头 / 时长加到 8 秒 / 换夜景）→ 改对应格，重摆卡片，再问。
- 模糊或无关回复 → 追问一次，仍不明确就保持等待。
- 例外（迭代）：用户基于上一条的修改指令（「换俯冲镜头」「再来一版更长」）→ 改对应格，**只摆变化格 + 新最终 prompt + 新规格**（delta 卡），等一个肯定词再提交；不必重摆未变的格。

## 生成

```bash
python "<skill-dir>/scripts/gen_media.py" video --prompt "<与拍板卡逐字一致的中文 prompt>" --resolution "1080P" --ratio "16:9" --duration 5
```

脚本提交、轮询、下载 MP4、打路径；在脚本超时内等它跑完。回报最终文件路径 + 一句效果观察 + 一个下一版方向；最终 prompt 已在拍板卡确认过，**不再重复贴**（用户问起再给）。MP4 本地存在前不许声称成功。

失败时：原文报 API 错误 + 拟采取的改动，等用户拍板再重试——不静默换模型。排查顺序：模型权限 → 渠道模型列表 → 额度 → 任务轮询服务。

## 迭代

交付后给恰好一个下一版方向（新角度/更长切片/换光线），然后停。

## 规则

- 只用自带脚本。
- Key 仅落 `~/.gen-media/config.json`；回复里 Key 一律掩码。
- 默认存当前工作目录，除非用户指定输出目录。

## 更新

用户要更新 gen-media → 走宿主的插件/技能更新机制（Claude Code：`/plugin update gen-media`；Codex/WorkBuddy：拉仓库重拷 skill 文件夹）。配置在 `~/.gen-media/config.json`，skill 目录之外，更新不影响。
